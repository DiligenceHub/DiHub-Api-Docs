Quando você cadastra um webhook, a DiHub faz um `POST` para a sua URL a cada evento: quando a diligência é criada, quando uma certidão muda de situação e quando a diligência termina. Vale para diligências criadas pela API e pelo Dashboard.

`diligence.created` → `certificate.updated` (a cada mudança de uma certidão) → `diligence.completed`

Cada entrega leva um corpo JSON e uma assinatura HMAC nos headers, no padrão [Standard Webhooks](https://www.standardwebhooks.com). Se o seu servidor não responder, a DiHub tenta de novo algumas vezes.

## Antes de começar

- **Token de API.** As rotas de webhook usam o mesmo header `X-Api-Token` do resto da API. Veja [Autenticação](/introduction/authentication).
- **Uma URL pública com HTTPS** no seu servidor para receber os eventos.
- **Um ambiente para testar.** Comece em homologação e repita o cadastro em produção. Cada ambiente tem os próprios webhooks e segredos.

| Ambiente | URL base |
| --- | --- |
| Produção | `https://api.dihub.com.br` |
| Homologação | `https://homolog.api.dihubapp.com` |

## Eventos

Cada evento marca um momento da diligência. No cadastro você escolhe quais quer receber.

| Tipo | Quando |
| --- | --- |
| `diligence.created` | A diligência foi criada. |
| `certificate.updated` | Uma certidão teve o status alterado. |
| `diligence.completed` | Todas as certidões da diligência terminaram. |
| `webhook.test` | Você pediu um teste. |

## Entrega e retentativas

Uma entrega conta como sucesso quando o seu servidor responde `2xx` em até 3 segundos. Qualquer outro status, redirecionamento, timeout ou erro de conexão conta como falha, e a DiHub tenta de novo algumas vezes: 1 minuto depois da primeira falha, depois de mais 5 minutos, depois de mais 30 minutos e, por último, depois de mais 2 horas. Todas as tentativas levam o mesmo `webhook-id`.

| Tentativa | Espera depois da anterior | Tempo desde o evento |
| --- | --- | --- |
| 1 | imediata | 0 |
| 2 | 1 min | 1 min |
| 3 | 5 min | 6 min |
| 4 | 30 min | 36 min |
| 5 | 2 h | 2 h 36 min |

- São no máximo **5 tentativas** por evento. Depois da última, a entrega fica `failed`.
- Responder `410 Gone` desativa o webhook na hora. Use quando a URL deixar de existir.
- Se o webhook passar 5 dias seguidos sem nenhuma entrega com sucesso, a DiHub desativa o webhook. O `GET /webhooks` mostra `isActive: false` e o motivo em `disabledReason`. Reative com `PATCH /webhooks/{id}`.

## Passo a passo

<Steps>
  <Step title="Prepare o endpoint">
    Crie no seu servidor uma rota que aceite `POST` com JSON. Ela precisa:

    - Usar `https`. O cadastro recusa `http`, `localhost` e IP privado.
    - Responder com status `2xx` em até **3 segundos**. Grave o evento numa fila e processe depois. A DiHub lê só o status da resposta e ignora o corpo.
    - Responder direto. Redirecionamentos (`301`, `302`) contam como falha.
  </Step>

    | Status | Quando |
    | --- | --- |
    | 400 | URL sem `https`, apontando para `localhost` ou IP privado, evento desconhecido em `events`, ou limite de 3 webhooks no escopo atingido. |
    | 401 | Token ausente, inválido ou vencido. |

  <Step title="Valide a assinatura">
    Antes de processar o corpo, confirme que ele veio da DiHub e não foi alterado. Toda entrega leva três headers:

    | Header | Conteúdo |
    | --- | --- |
    | `webhook-id` | Id do evento, como `evt_6f1c2a90…`. É o mesmo em todas as tentativas do mesmo evento. |
    | `webhook-timestamp` | Momento do envio, em segundos Unix. |
    | `webhook-signature` | Uma ou mais assinaturas separadas por espaço, no formato `v1,<base64>`. |

    1. Tire o prefixo `whsec_` do segredo e decodifique o resto de base64. O resultado é a chave.
    2. Monte o texto `{webhook-id}.{webhook-timestamp}.{corpo}` com o corpo cru, exatamente como chegou. Não parseie o JSON antes.
    3. Calcule o HMAC-SHA256 desse texto com a chave e codifique em base64.
    4. Compare com cada assinatura `v1` do header, em tempo constante. Basta uma bater.
    5. Rejeite se o `webhook-timestamp` estiver a mais de 5 minutos do seu relógio.

    <CodeGroup>
    ```text Prompt para IA
    # Cole no Claude Code (ou no assistente de IA que você usa) dentro do seu projeto.

    Crie no meu projeto uma rota POST /webhooks/dihub para receber os webhooks da DiHub.

    Siga a documentação oficial: https://docs.dihub.com.br/webhooks/webhooks

    - Valide a assinatura dos headers webhook-id, webhook-timestamp e webhook-signature
      com o segredo da variável de ambiente DIHUB_WEBHOOK_SECRET.
    - Use o corpo cru da requisição na validação.
    - Recuse se a assinatura não bater ou se o timestamp tiver mais de 5 minutos.
    - Responda 200 em menos de 3 segundos e processe o evento depois.
    - Ignore eventos repetidos pelo webhook-id.
    ```

    ```javascript Node.js
    import express from 'express'
    import crypto from 'node:crypto'

    const secret = process.env.DIHUB_WEBHOOK_SECRET // whsec_...
    const key = Buffer.from(secret.replace(/^whsec_/, ''), 'base64')

    const app = express()

    // express.raw mantém o corpo cru, que é o que a assinatura cobre
    app.post('/webhooks/dihub', express.raw({ type: 'application/json' }), (req, res) => {
      const id = req.header('webhook-id')
      const timestamp = Number(req.header('webhook-timestamp'))
      const signatures = (req.header('webhook-signature') ?? '').split(' ')

      if (!id || Math.abs(Date.now() / 1000 - timestamp) > 300) return res.sendStatus(400)

      const expected = crypto
        .createHmac('sha256', key)
        .update(`${id}.${timestamp}.${req.body}`)
        .digest()

      const valid = signatures.some((entry) => {
        const [version, value] = entry.split(',')
        if (version !== 'v1' || !value) return false
        const received = Buffer.from(value, 'base64')
        return received.length === expected.length && crypto.timingSafeEqual(received, expected)
      })
      if (!valid) return res.sendStatus(401)

      queue.add(JSON.parse(req.body)) // processe depois e responda logo
      res.sendStatus(200)
    })
    ```

    ```python Python
    import base64, hashlib, hmac, os, time
    from flask import Flask, abort, request

    secret = os.environ["DIHUB_WEBHOOK_SECRET"]  # whsec_...
    key = base64.b64decode(secret.removeprefix("whsec_"))

    app = Flask(__name__)

    @app.post("/webhooks/dihub")
    def dihub_webhook():
        msg_id = request.headers.get("webhook-id")
        timestamp = request.headers.get("webhook-timestamp", "0")
        signatures = request.headers.get("webhook-signature", "").split()

        if not msg_id or abs(time.time() - int(timestamp)) > 300:
            abort(400)

        body = request.get_data()  # corpo cru
        signed = f"{msg_id}.{timestamp}.".encode() + body
        expected = base64.b64encode(hmac.new(key, signed, hashlib.sha256).digest()).decode()

        valid = any(
            hmac.compare_digest(entry.split(",", 1)[1], expected)
            for entry in signatures
            if entry.startswith("v1,")
        )
        if not valid:
            abort(401)

        enqueue(request.get_json())  # processe depois e responda logo
        return "", 200
    ```

    ```text Biblioteca oficial
    # A biblioteca do Standard Webhooks confere a assinatura e o horário.

    import { Webhook } from 'standardwebhooks'

    const wh = new Webhook(process.env.DIHUB_WEBHOOK_SECRET.replace(/^whsec_/, ''))
    const event = wh.verify(rawBody, headers) // lança erro se a assinatura não bater
    ```

  <Step title="Emita uma diligência e acompanhe">
    Emita com [`POST /diligences/emit`](/api-reference/diligences/emit) usando o mesmo token. Os eventos chegam nesta ordem típica:

    1. `diligence.created`, logo depois da criação.
    2. Um `certificate.updated` a cada mudança de situação de uma certidão.
    3. `diligence.completed`, quando todas as certidões terminam.

    Quando um `certificate.updated` chegar com `label` igual a `Concluída`, baixe o PDF pelo `certificate.fileUrl`. Se o link já tiver vencido, use [`GET /certificate/{id}/download-pdf`](/api-reference/certificates/download-pdf) com o `certificate.id` do evento.

## Webhooks da organização

Se a sua conta faz parte de uma organização, um webhook pode receber as diligências de todos os membros.

- **Permissão.** Só quem tem **Gerenciar webhooks** cadastra com `"scope": "organization"`. Administradores da organização têm por padrão.
- **O webhook é da organização.** Quem tem a permissão vê, edita e remove. Se quem cadastrou sair da organização, o webhook continua funcionando.
- **O que chega.** Os eventos de qualquer diligência criada por um membro, pela API ou pelo Dashboard.

<Note>
  Se você tem um webhook de usuário e outro da organização, as suas diligências chegam nos dois. Use URLs diferentes ou descarte repetidos pelo `webhook-id`.
</Note>

### Trocar o segredo

O segredo antigo é cancelado na hora: a partir da troca, toda entrega sai assinada só com o segredo novo. Atualize o segredo no seu sistema logo depois de chamar a rota, senão a sua validação vai recusar as próximas entregas.

```json Resposta 200
{
  "statusCode": 200,
  "message": null,
  "data": {
    "id": "3f6c1e2a-8b4d-4c7e-9a10-5d2b7e9c4f01",
    "secret": "whsec_P7wz1Rk9…"
  }
}
```

## Boas práticas

- **Responda rápido.** Grave o evento e devolva `200`. O processamento fica para depois.
- **Combine o webhook com a API.** Se o `diligence.completed` chegar antes de algum `certificate.updated`, é porque uma entrega ficou para trás na retentativa. Nesse caso, consulte [`GET /diligences/{id}/status`](/api-reference/diligences/status) e [`GET /diligences/{id}/certificates`](/api-reference/diligences/certificates): a API sempre responde com a situação em tempo real.
- **Não conte com a ordem de chegada.** Uma entrega que falhou é refeita minutos ou horas depois, então um evento pode chegar depois de outro mais novo.
- **Descarte repetidos pelo `webhook-id`.** Uma retentativa pode chegar depois de você já ter processado o evento, por exemplo quando a sua resposta se perde na rede.
- **Ignore tipos que você não conhece.** Responda `200` e siga. Eventos novos só chegam se você assinar, mas o `webhook.test` chega sempre.
